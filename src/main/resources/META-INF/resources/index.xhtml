Ciclo do Raciocínio Baseado em Casos

Um caso é a descrição do problema (atributos do módulo, cada um com peso) mais a solução. A busca percorre os casos desse módulo e devolve os mais parecidos.

1. Recuperar

Cada atributo recebe uma similaridade local. A global é a média ponderada: soma de peso × similaridade, dividida pela soma dos pesos. Campo em branco entra com 0 e o peso continua na conta. A lista traz até 10 casos, do maior percentual para o menor. Empate prefere o caso validado e, depois, o mais recente. Percentual 0 não aparece.

2. Reutilizar

Aplicar copia a solução do caso escolhido. Onde o texto cita um valor do caso antigo (uma UF, um código, um status), esse valor é trocado pelo do problema novo. Palavra que o dicionário trata como igual não é trocada.

3. Revisar

O caso retido nasce pendente. O técnico ajusta a solução, pode acrescentar um complemento e marcar o caso como validado. Só então ele pesa como caso confirmado nas próximas buscas.

4. Reter

Grava a descrição e a solução. Se a solução veio de um caso recuperado, ficam guardados o caso de origem, a similaridade e as trocas feitas. Uma descrição já existente com a mesma solução não é gravada de novo.

Como cada atributo é comparado

Número

Medida escalar: 1 − |a − b| / (máximo − mínimo) dos valores desse atributo no módulo, incluindo o problema novo. Códigos de rejeição próximos ficam com percentual alto.

Texto

Contagem de palavras em comum, depois de tirar acento e palavra irrelevante. O dicionário une sinônimos: NFe, nota fiscal e NF contam como a mesma palavra.

Tabela

Se o atributo tem pares em Similaridade local, a busca usa essa tabela no lugar do texto. O par vale só no sentido consulta → caso. Sem par cadastrado, vale número ou texto.

O que a base já tem

Casos de NF-e, NFC-e, SAT, PDV, TEF, estoque, financeiro e cadastros, com revisão de técnico em parte deles. A tabela local cobre tipo de NF-e, ambiente, UF, status e forma de pagamento.
